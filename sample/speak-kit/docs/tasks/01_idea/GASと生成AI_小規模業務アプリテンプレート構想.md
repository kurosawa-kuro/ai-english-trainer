# GASと生成AIによる小規模業務アプリ・テンプレート構想

**副題：プログラミング未経験者のための業務アプリ・テンプレートと動画教材**

作成日：2026-10-23  
ステータス：企画・技術選定段階  
現行案：Devin Free ＋ GAS ＋ 完成テンプレートZIP ＋ 動画教材  
想定開発工数：アプリ1日＋動画教材1日（目標。確約納期ではない）

---

## 1. 結論

完成済みテンプレートを Devin Desktop で開き、日本語で指示するだけで、自分専用の業務アプリへ改修できる状態を提供する。

標準構成は次のとおり。

**Devin Free ＋ GAS ＋ Google Sheets ＋ Google Drive ＋ 完成テンプレートZIP ＋ 動画教材**

- 利用者に求めるのは、Devin への日本語の依頼と、画面に出た Google のログイン・承認だけである。
- 配布は ZIP とし、利用者の GitHub アカウントは不要にする。
- AI が行うのは、同梱済みテンプレートの差分変更と、用意済みコマンドの実行である。
- 日常のアプリ利用に Devin は不要である。起動するのは修正・更新・復旧のときだけにする。
- デプロイ手順はテンプレートのスクリプトに固定する。
- 標準は Devin Free。独自改修が増えた利用者だけが Pro（月20ドル）を検討する。
- 黒澤は本番環境を継続管理しない。成功条件は、継続的な開発・保守の窓口から離脱できること。

同日の前案（Claude Code／Codex ＋ GitHub Template）は、利用者に Git 操作と GitHub アカウントを求めるため現行案から外した。残した内容と外した理由は「16. 決定ログ」。

## 2. 目的

**黒澤による初期導入後のフォロー・サポートを可能な限り早く終了すること。**

利用者の自走はその手段である。完成後も開発者が保守し続ける受託にはしない。

優先順位：

1. 黒澤側の継続サポート工数を最小化する
2. 非エンジニアの導入障壁を最小化する
3. AI開発コストを最小化する
4. テンプレートを再利用可能にする
5. 利用者自身による独自カスタマイズを可能にする

高度な技術の導入や、総合業務システムを作ること自体は目的にしない。

最重要KPIは、納品後に黒澤が拘束される追加サポート時間。目標は原則ゼロ。

工数の置き方：

- 初回開発と動画制作は、共通資産として一度だけ行う
- 個別の環境構築支援は最小化する
- 個別改修は利用者＋AIが行う
- 通常運用は利用者が行う
- 一般的な障害復旧は利用者＋AIが行う

## 3. 想定利用者と対象業務

主な対象：

- プログラミング経験のない個人事業主
- スナック・飲食店などの小規模事業者
- 副業から独立開業を目指す個人
- 店主と少人数スタッフで業務を管理する利用者
- 自分専用の業務アプリが欲しいが、継続的な開発委託費を負担したくない人

発端は、ITに詳しくない利用者からの、店主とアルバイト・メンバー間のポイント管理の相談。将来的には、現役引退後の副業やスナックなどの独立経営につながる可能性がある。事業計画とポイント制度の詳細は未確定。

ホットペッパーなど既存サービスが担う機能は重複して作らない。既存サービスの代替ではなく、その隙間にある内部業務を補完する。

開発対象外：

- 集客・広告
- 予約管理
- 顧客向け投稿・写メ日記
- 既存サービスが提供する顧客CRM
- 既存の顧客向けポイント制度
- 給与計算、現金精算、外部POS連携

独自開発の対象：

- メンバーへのポイント付与・減算
- ポイント残高の確認
- 操作履歴の管理
- ポイント付与ルールの設定
- 店主とメンバーの権限制御

## 4. 採用技術

| 領域 | 採用技術 |
|---|---|
| AI開発環境 | Devin Desktop |
| AI契約 | Freeで検証。独自改修が増えた場合だけ Pro（月20ドル） |
| 言語 | JavaScript / TypeScript |
| バックエンド | Google Apps Script（GAS） |
| データ保存 | Google Sheets |
| 画像保存 | Google Drive |
| フロント① | GAS HTML Service |
| フロント② | LINE連携（LIFF等。要検証） |
| ローカル開発 | Node.js ＋ clasp |
| デプロイ | clasp（`npm run deploy` に固定） |
| 配布 | ZIP。利用者の GitHub アカウントは不要 |
| ソース管理 | 黒澤側は必要なら Git。利用者の必須操作にはしない |
| テスト | 自動テスト＋実環境確認 |
| 操作説明 | 動画＋Markdown |

### Devin Desktop

利用者がローカルのテンプレートを開き、自然言語で改修を指示する環境。GitHub・GitLab のアカウントは必須にしない。

インストール、ログイン、モデル利用枠、対応OSは、対象PCで事前確認する。

現行の Devin 公式プランに「Hobby」はない。該当するのは Free（$0）。Free でも Desktop の AI エージェントは使える。利用枠とモデルに制限がある。Pro でも使用量で追加料金が出る可能性があるため、月額だけで評価しない。

clasp は Google 公式の GAS 管理 CLI で、デプロイと既存デプロイの更新に対応する。clasp 自体に Devin Pro は不要。

| 作業 | Freeの適性 |
|---|---|
| テンプレートZIPを開く | 対応 |
| Sheetsの初期設定支援 | 可能 |
| `clasp login` の案内 | 可能 |
| `clasp push` と GASデプロイの実行支援 | 可能 |
| 軽微なUI修正 | 利用枠内で可能 |
| 月に数回の軽微な改修 | Freeから検証。枠次第 |
| 頻繁な独自カスタマイズ | Pro が有力 |
| 大規模な改修・開発 | Pro以上を個別判断 |

Free の利用枠は、エラー調査と再試行の繰り返しで使い切る可能性がある。認証の期限切れや Google 側の仕様変更は、完全自動では解けない。非エンジニア環境で、初期セットアップからデプロイとロールバックまで Free だけで完走できるかを1回検証する。

### GASを選ぶ理由

Next.js＋Vercel／Cloudflare と比べ、今回の規模では管理対象を減らせる。

- 独立したWebサーバーと外部DBが不要
- Sheets をデータ保存先、Drive を画像保存先にできる
- Googleアカウントに所有権を集約できる
- 複数クラウドの初期契約を省略できる
- 小規模なら無料枠内で運用できる可能性が高い
- clasp でローカル開発とデプロイを管理できる
- 利用者へインフラの所有権を移しやすい

### Sheetsで扱う範囲

対応する範囲は、単純CRUD、1対多、多対多（中間テーブル）、小規模な集計・検索、操作履歴、業務ルール管理。

制約は次のとおり。外部キーはない。JOIN は GAS 側で実装する。トランザクション保証は限定的。同時更新には LockService 等を使う。複雑な集計と大量データには向かない。

テーブル数や多対多だけを理由に PostgreSQL 等は導入しない。ポイント台帳の更新は、追記型と重複防止で整合性を取る。

## 5. テンプレート

題材は2種類、技術構成は3パターン。

| Phase | テンプレート | フロント | バックエンド | 目的 |
|---|---|---|---|---|
| α-① | Instagram風フォト投稿 | GAS HTML Service | GAS＋Sheets＋Drive | 基本CRUD・画像管理 |
| α-② | 同上 | LINE連携 | GAS＋Sheets＋Drive | LINE連携の検証 |
| β-② | スタッフポイント管理 | LINE連携。不可なら GAS HTML | GAS＋Sheets | 初期相談者向けの実用テンプレート |

LINE が成立しなくても GAS完結型は残す。LINE が使えなくても、アプリ全体の提供は止めない。

### α-① フォト投稿（GAS完結）

GASによる業務Webアプリの基本構成を確立する。名称は「PhotoLog」など汎用名にする。

- 投稿のCRUD
- 画像のアップロード・削除、Driveへの保存、Sheetsへのメタデータ
- カテゴリー（1対多）
- タグ（多対多）と、タグ検索・一覧
- 最小限の権限・ユーザー管理

Instagramの完全再現はしない。いいね、フォロー、DM、通知、レコメンドは対象外。

### α-② LINE連携フォト投稿

α-①の業務ロジックを再利用し、LINEフロントを足す。ここで確立した連携を β-② で再利用する。重点は LINE認証と GAS間通信。

- LINE画面の表示とユーザー認証
- GASとの通信
- 投稿CRUD、画像アップロード
- アクセス制御、デプロイ

### β-② スタッフポイント管理

初期相談者向け。初期サンプルは「勤務・貢献評価型」。基盤は業務に依存しない汎用ポイント台帳とし、売上・指名・出勤などのルールは利用者が変えられるようにする。

- メンバー登録・編集
- ポイント付与・減算
- 残高確認
- 取引履歴（訂正・取消を含む）
- 付与ルール設定
- 店主・メンバーの権限管理

### LINEの注意

性風俗・ナイト系では、LINEミニアプリ等の利用ポリシーと、認証・通信の制約を確認する。条件を満たさない場合の業務フロントは、GAS単独のWebアプリにする。

未検証の項目：

- LIFF画面とGASの通信方式
- GASのリダイレクト・CORS制約
- LINE認証情報のバックエンド検証
- LINEミニアプリ・公式アカウントの対象業種制限
- LINE Bot方式にする場合のWebhook署名検証

## 6. ポイント台帳

残高は直接上書きしない。取引を追記し、残高は履歴の集計で求める。取消は逆仕訳で記録する。二重送信を防ぐ。ルールは Sheets 上で変更できる。増減の整合性は自動テストで検証する。

### members

- id
- name
- status
- external_user_id（必要な場合）

### point_rules

- id
- name
- category
- default_points
- enabled

### point_transactions

- id
- member_id
- rule_id
- points
- reason
- created_by
- created_at
- reversal_of（取消時）

## 8. AIの使い方

最初から CRUD、データ構造、バリデーション、認証・権限、テスト、デプロイ、復旧、AI向け開発ルールを同梱する。利用者の依頼は差分だけにする。

改修例：

- ボタンをピンク色に変更したい
- 新人指導のポイントを20ポイントにしたい
- メンバーの月間ランキングを追加したい
- ポイント履歴を日付で絞り込みたい
- 退職したメンバーを非表示にしたい

テンプレートに同梱する原則：

1. 依頼に必要なファイルだけを変更する
2. 既存機能を壊さない
3. Coreの変更は原則禁止
4. データ削除や権限変更は、利用者の明示がない限り実行しない
5. 変更前後に自動テストを実行する
6. テスト失敗時にはデプロイしない
7. 本番更新前に利用者の承認を求める

デプロイ手順は AI に考えさせない。テンプレート側のコマンドは次のとおり。

```bash
npm run setup
npm run test
npm run deploy
npm run backup
npm run restore
```

`restore` は、コードの切り戻しと、Sheets・Drive の復元を分けて扱う。

利用者から Devin への指示例：

```text
アプリを更新したいです。テストしてからデプロイしてください。途中でGoogleのログインや確認が必要なら教えてください。
```

Devin が行うのは、既存コマンドの実行と結果確認。初回の Google 認証と本番反映の承認は利用者自身が行う。OSごとの Node.js 導入、OAuth 認可、GAS の公開設定だけ、必要な箇所を利用者が操作する。コマンドの暗記は求めない。

テンプレート利用時の AI 消費量を測り、ゼロから開発した場合と比較する。

## 9. 配布・導入・所有権

黒澤側は開発に Git を使ってよい。利用者への配布は ZIP。

導入手順：

1. Devin Desktop をインストールしてログインする
2. テンプレート ZIP をダウンロードして解凍する
3. Devin Desktop でフォルダを開く
4. セットアップ手順を実行し、自分の Google アカウントを認可する
5. GAS アプリを公開する
6. 日本語で機能変更を依頼する

GitHub アカウントの作成、clone、push は必須にしない。

所有権：

- GAS、Sheets、Drive は利用者の Google アカウントに置く
- Devin は利用者本人の契約にする
- アプリのデータは利用者本人が管理する
- 黒澤は本番を継続管理しない
- パスワードは共有しない
- 店主所有の Google アカウントに資産を集約する
- 利用者認証と、操作した人の識別は分ける
- Drive の画像閲覧権限を制御する
- 黒澤側が Git を使う場合も、認証情報と業務データはコミットしない

## 10. 動画教材

プログラミング講座ではなく、一人で導入・改修・復旧するための操作マニュアルとして作る。

| 動画 | 内容 | 目的 |
|---|---|---|
| ① 導入 | Devin Desktopの導入・ログイン | 環境構築 |
| ② テンプレート | ZIPの解凍、フォルダを開く | 開発開始 |
| ③ GAS公開 | Google認証、デプロイ | アプリ起動 |
| ④ AI改修 | 日本語でUI・機能を変更する。デプロイは用意済みコマンドを指示する | 独自カスタマイズ |
| ⑤ テスト | 変更結果と動作の確認 | 品質維持 |
| ⑥ 復旧 | 更新失敗から前の状態へ戻す。コードと、Sheets・Drive のデータを分けて示す | 自己解決 |

収録方針：

- 初心者が実際に操作する順で収録する
- 1動画1テーマにする
- 操作に必要な画面だけ説明する
- 同じ手順を Markdown でも置く
- 対応バージョンを明記する
- エラー時の手順を用意する

教える範囲は、Devinへの依頼、改修結果の確認、テスト、デプロイ、バックアップ、トラブル時の復旧。

教材に含めない範囲は、言語の体系的な学習、Gitコマンド、データベース設計の理論、Next.js 等のフレームワーク、クラウドインフラの構築。

## 11. サポートの終了

提供物：

- 完成テンプレートZIP
- 初期セットアップ手順
- AI向け指示ファイル
- 動画マニュアル
- 自動テスト
- バックアップ・復旧手順
- よくあるエラーのFAQ

黒澤が行うのは、初期導入と、事前に合意した範囲の操作説明。利用者独自の機能追加、業務仕様の変更、AI契約の問い合わせは対象外。

終了条件は、利用者が次を再現できた時点。

- Devin Desktop を起動し、テンプレートを開ける
- 自分の Google アカウントで GAS を動かせる
- 日本語で軽微な改修を依頼できる
- テスト結果を確認できる
- 修正版をデプロイできる
- 問題発生時に、以前の正常な状態へ戻せる

コードのロールバックと、Sheets・Drive の復元は別に検証する。対象範囲、終了時点、終了後の追加対応条件は、納品前に文章で合意する。

## 12. 開発計画

目標は実働2日。黒澤の開発経験と AI 活用を前提とした目標であり、確約納期ではない。

| 日程 | 作業 |
|---|---|
| Day 1 | 共通基盤、α-①、α-②、β-②。LINE認証とGAS間通信は初日の早い段階で検証する |
| Day 2 | ZIP整備、セットアップ手順、動画収録 |

検証の順：

1. Devin Desktop から GAS を安全に改修し、反映できる（最優先）
2. ZIP だけで Git ホストを不要にできる
3. 利用者自身の Google アカウントへ初回デプロイできる
4. Free だけで、非エンジニア環境のセットアップからデプロイ・ロールバックまで完走できる
5. Sheets・Drive 連携、差分改修、テスト、ロールバックができる
6. LINE が業種と技術条件を満たすか。満たさなくても GAS完結型は残す

## 13. リスク

警戒の中心は、利用者が導入・認証・公開・復旧のいずれかで詰まり、黒澤への問い合わせが再発すること。

| リスク | 対策 |
|---|---|
| Devinの導入が難しい | 動画と初期設定の自動化 |
| Freeの利用枠を使い切る | 差分改修に限定し、Coreを分離し、デプロイはスクリプトにする。枠は実測する |
| AIが既存コードを破壊する | 自動テスト、変更範囲の制限、失敗時はデプロイしない |
| ポイント残高が不整合になる | 追記型台帳、重複防止、LockService |
| Google認証で止まる | 認可手順を動画にする。期限切れは完全自動にしない |
| GASの利用制限、Sheetsの肥大 | 小規模用途に限定し、使用量を見る |
| LINEの利用条件に抵触する | GASの独立Web画面へ切り替える。業務ロジックは分離する |
| 更新後に障害が出る | デプロイ版の管理と復旧手順 |
| データが消える | 定期バックアップ。コードとデータを分けて復元する |
| 動画が古くなる | 対応バージョンを固定する。DevinのUI変更を見る |
| Google側の仕様が変わる | 動画とスクリプトの更新対象にする |

あわせて確認するもの：OAuth と GAS の公開設定、Drive の画像権限、バックアップ手順、AIの誤変更、デプロイ失敗時の切り戻し。

## 14. 次に確認すること

### 優先度A（最初に実証する）

- Devin Free で対象テンプレートを扱えるか
- ZIP配布だけで Git ホストを不要にできるか
- 利用者自身の Google アカウントへ初回デプロイできるか
- 非エンジニアが動画に沿い、セットアップからデプロイ・ロールバックまで Free だけで再現できるか

### 優先度B（基盤ができたときに検証する）

- AI差分改修に必要な利用量（ゼロから開発した場合との比較）
