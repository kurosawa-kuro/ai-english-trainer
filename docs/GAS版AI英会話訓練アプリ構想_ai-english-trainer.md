# GAS版 AI 英会話訓練アプリ構想（`ai-english-trainer`）

**副題：AI の採点と会話を目玉に、Google アカウントだけで始められる英語訓練アプリ**

作成日：2026-10-24
状態：**アイディア（生）**。着手の承認ではなく、実装仕様でも Phase 合格条件でもない
方針：**エンジン（出題・台帳・採点・AI 制御）は参照元 `speak-kit` を踏襲し、教材の持ち方は新しくする**

この文書で「参照元」と書いたら、このリポジトリ内の `sample/speak-kit/`（Next.js 実装の実物コピー）を指す。**外のリポジトリは見ない。** 扱いは 3 章。

---

## 1. 結論

参照元 `speak-kit` の学習エンジン（出題選択・追記型台帳・採点判定・AI の可否と上限）をそのまま持ち込み、実行基盤を **Google Apps Script ＋ Google Sheets** に置き換えたアプリを、このリポジトリ `ai-english-trainer` に作る。

**売り物は AI である。** 自由記述を書いて「伝わったか」を返してもらうこと、AI と会話することが、利用者がこのアプリを開く理由である。選択式クイズはその土台にすぎない。

AI は **Google の Gemini API を、Google AI Studio の無料枠で使う**（2.2）。

同時に、Sheets に載ることで参照元にできないことが 1 つできる。**教材を利用者が自分で編集できる**（4.0）。

### 名前

配布版はこの 1 本だけである。

| リポジトリ | 中身 | 役割 |
|---|---|---|
| **`ai-english-trainer`**（ここ） | GAS ＋ Sheets | 配る物。**作成済み** |

名前の根拠は、特徴量が **AI・英語・訓練**の 3 つだからである。旧名 `speak-kit` は音声を作らない（非対象と明記）のに `speak` を名乗り、3 つのどれも表していない。

`english`（`eikaiwa` ではない）を採るのは、教材を利用者が編集できるようにすると、扱える範囲が会話表現に限らなくなるためである。**英会話は黒澤の初期教材の性質であって、エンジンの制約ではない。**

## 2. なぜ GAS 版を作るか

### 2.1 参照元の配布は、目玉に届く前に脱落する

参照元の配布は、相手に次を要求する。

| # | 要求 | 相手の作業 |
|---|---|---|
| 1 | GitHub アカウント | 作成、clone または fork |
| 2 | Vercel アカウント | 作成、GitHub 連携、デプロイ |
| 3 | Supabase アカウント | 作成、プロジェクト作成、リージョン選択、接続文字列の取得 |
| 4 | 環境変数 4 本 | `SPEAK_KIT_DATABASE_URL`、`SPEAK_KIT_DATABASE_KIND`、`SPEAK_KIT_PASSWORD`、`ANTHROPIC_API_KEY` |
| 5 | DB の形と教材の投入 | `make cloud-db`、`make cloud-data` |
| 6 | **Anthropic の契約とキー取得** | **アカウント作成、課金設定、キー発行** |

英会話コミュニティの知人の大半は、1〜5 のどこかで止まる。**そして 1〜5 は、目玉（6 の先にある AI）にたどり着く前の雑務である。**

GAS 版の要求は次に縮む。

| # | 要求 | 相手の作業 |
|---|---|---|
| 1 | Google アカウント | すでに持っている |
| 2 | コピー | スプレッドシートで「ファイル > コピーを作成」 |
| 3 | 初期化 | メニューから「初期設定」を 1 回押す |
| 4 | **Gemini API のキー** | **残る。ただし Google AI Studio で発行でき、カード登録は要らない（2.2）** |

**1〜3 で消えるのは「雑務の側」であり、目玉の鍵は残る。** GAS 化の効果を正しく数えると、ここが肝心である。残る鍵を軽くするのが 2.2 の Gemini 化である。

### 2.2 残る唯一の壁は AI の鍵。Gemini API の無料枠で軽くする

目玉が AI である以上、**配布の本当の問題はここ 1 点に凝縮される。**

- Anthropic を前提にすると、「GitHub でアカウントを作って」より「Anthropic でアカウントを作って、クレジットカードを登録して、キーを発行して、貼り付けて」の方が重い可能性がある
- キーを入れない相手に残るのは選択式クイズだけで、それは**単語カードであって英会話訓練ではない**
- 動画の「まず AI 無しで動かす」は**セットアップの順序**であって、そこを終着点にしてはいけない

**そこで AI を Google の Gemini API に替え、Google AI Studio の無料枠を前提にする**（owner 決定 2026-10-24）。

| | Anthropic（旧前提） | **Gemini API 無料枠（採用）** |
|---|---|---|
| アカウント | 新規作成 | **いま使っている Google アカウント** |
| クレジットカード | 要る | **要らない** |
| 費用 | 従量課金 | **無料。** 上限に達すると 429 で止まるだけで、請求は起きない |
| GAS からの宛先 | `api.anthropic.com` | `generativelanguage.googleapis.com` |

無料枠の条件（[料金](https://ai.google.dev/gemini-api/docs/pricing) 2026-10-22 更新版・[利用規約](https://ai.google.dev/gemini-api/terms) 2026-04-28 更新版を 2026-10-24 に確認）：

- 対象は Flash / Flash-Lite 系。新しい Pro は無料枠に無い。**使うモデル名は実装時に料金ページで確かめ、設定値に置く**（コードに埋め込まない）
- 回数の上限はプロジェクト単位で、AI Studio の画面で確かめる。モデル別の一覧表は公開されていない
- **入力と出力は Google の製品改善に使われ、人間のレビュアーが読むことがある。** 規約は「機密・個人情報を無料枠へ送らない」と書いている（4.4 の注意表示）
- 18 歳以上が条件。EEA・英国・スイスの利用者へ提供するなら有料版だけ
- キーを発行するプロジェクトで課金を有効にしない。有効にすると有料版の扱いになり、請求が起き得る

AI の可否判定（4.3）、同期採点（D4）、観測から 5 判定への落とし方（4.7）は変えない。変わるのは AI の窓口 1 か所の呼び先（D16）と、4.4 の装置である。

鍵は軽くなったが、この構想で解くべき最重要の設計問題は依然として「GAS にどう移すか」ではなく、**誰の鍵で目玉を動かすか**である（8.3 の配布モデル A / B / C）。

### 2.3 認証・本人確認は「簡易化」ではなく「消える」

参照元の認証まわりは、仕組みが未完成のまま配布直前で止まっている。

| 層 | 現状 |
|---|---|
| 画面と API の保護 | [middleware.js](../sample/speak-kit/src/middleware.js) ＋ [guard.mjs](../sample/speak-kit/src/server/http/guard.mjs) の**合言葉（Basic 認証）**。ユーザー名は見ない |
| 合言葉の配布 | `env/secret.yaml` の値を Vercel の環境変数 `SPEAK_KIT_PASSWORD` に入れる。相手ごとに別の値を決めて伝える必要がある |
| 設定し忘れの防御 | Vercel 上で未設定なら 503 で誰にも開かない（`misconfigured`） |
| 本人の識別 | **無い。** `learnerKey` は `"default"` の固定値（[config.mjs](../sample/speak-kit/src/server/config.mjs)） |
| 本来のログイン | Supabase Auth。**「足すことは確定、やり方は未決」のまま後回し**（[01_requirements.md](../sample/speak-kit/docs/01_requirements.md)、[05_data_model.md](../sample/speak-kit/docs/05_data_model.md)、[04_workflows.md](../sample/speak-kit/docs/04_workflows.md) の 3 文書に同じ保留が書かれている） |

配布を始めると、この仮の壁が次を生む。

- 相手ごとの合言葉を黒澤が決めて伝える（鍵の受け渡しが発生する）
- 相手が忘れる → 黒澤へ問い合わせ
- `SPEAK_KIT_PASSWORD` を入れ忘れた相手のインスタンスは 503 のまま → 問い合わせ
- Supabase Auth の未決を、配布後にいつか解く義務が残る

GAS 版では、この列が丸ごと消える。

| 消えるもの | 置き換わるもの |
|---|---|
| 合言葉そのもの | Google のログイン（相手はすでに済ませている） |
| `middleware.js` ＋ `guard.mjs` ＋ 401 応答 | Google 側の ACL |
| `SPEAK_KIT_PASSWORD` の配布・忘却・設定漏れ | 無し（渡す秘密が 1 つも無い） |
| 503 の設定漏れ防御 | 無し（設定項目が無いので漏れようが無い） |
| Supabase Auth の未決 | **決める必要がなくなる** |
| 本人の識別が無いこと | `Session.getActiveUser().getEmail()` が最初からある（条件つき。8.3） |

#### アクセス設定は 4 つしかない

`appsscript.json` の `webapp.access` に指定できるのは次の 4 つだけである（[公式マニフェスト](https://developers.google.com/apps-script/manifest/web-app-api-executable)、2026-10-24 確認）。

| 値 | 意味 | 使えるか |
|---|---|---|
| `MYSELF` | デプロイした本人だけ | モデル A |
| `DOMAIN` | 同じ Workspace ドメインの人だけ | **使えない。** 個人 Gmail にドメインが無い |
| `ANYONE` | Google にログインしている人なら誰でも | 単体では広すぎる。二重の門番が要る（モデル B・C） |
| `ANYONE_ANONYMOUS` | ログイン不要で誰でも | 論外 |

**「許可した N 人だけ」という設定値は無い。** Google が入口で強制してくれる狭い設定は `MYSELF` だけである。特定の数人に開くには `ANYONE` にしたうえで、アクセス制御を**アプリ側か Drive 側に自分で置く**（8.3）。

**代償が 1 つある。** 初回の OAuth 承認で「このアプリは Google で確認されていません」の警告が出る。非エンジニアには、合言葉の入力欄より怖い画面である。承認を初期設定の 1 回に集約し、動画でこの画面を名指しで見せる。

## 3. 参照元の扱い

このリポジトリの世界は 2 つだけである。**外のリポジトリは見ない。**

| 場所 | 役割 | 書き込み |
|---|---|---|
| `src/`（これから作る） | GAS + Sheets の配布版。**作る物はここだけ** | する |
| `sample/speak-kit/` | Next.js 実装の実物コピー。挙動・SQL・文言・教材を**読むための参照元** | **しない** |

規律：

- この文書のコード参照はすべて `sample/speak-kit/` を指す。他の場所のパスを書かない
- `sample/speak-kit/` を変更しない。更新が要るなら、取り込み直して差し替える
- `sample/speak-kit/` のコードを `src/` へ丸ごとコピーしない。読んで、GAS 版として書き直す（5）
- `sample/speak-kit/` 側の計画・残作業・未決は引き継がない。**参照元は「動いている実装の見本」であって、このリポジトリの計画ではない**

**配布版は GAS 版 1 本に絞る。** 参照元が持っていた Next.js 版の派生計画は、このリポジトリの計画に含めない。

## 4. 思想：どこを踏襲し、どこを新しくするか

### 4.0 分岐点

参照元の構造には、**Postgres が安かったから作れたもの**と、**47 タスクかけて詰めた判断ロジック**が混ざっている。前者を捨て、後者を残す。

| 層 | 扱い | 理由 |
|---|---|---|
| 出題選択の規則（4.6） | **踏襲** | 間隔・昇格・ゲート・混同優先は、実際に学習が進む形に調整した結果。スタックに依存しない |
| 追記型台帳と冪等再送（4.7） | **踏襲** | 整合性の土台 |
| 採点の 5 判定と学習者向け文面（4.7） | **踏襲** | 文面まで含めて調整済み |
| AI の可否 3 理由（4.3） | **踏襲** | 1 回の操作の最初に 1 度だけ決める規律ごと移す |
| 利用上限・円表示（4.4） | **作り替える** | Gemini の無料枠（2.2）では請求が起きない。不安の中身が「いくら払うか」から「止まらないか・どこへ送られるか」に変わる |
| **教材の正本** | **新しくする（4.8）** | Sheets だからできることの本体 |
| **データモデル** | **新しくする（6）** | 30 表は Postgres の都合。Sheets には重すぎる |

### 4.1 画面構成（踏襲）

[tabs.js](../sample/speak-kit/src/app/_components/tabs.js) の 5 タブをそのまま。

| タブ | 内容 |
|---|---|
| 今日 | 今日の計画 |
| 練習 | クイズ（選択式）とテキストフォーム（自由記述）、練習方法の切り替え |
| 会話 | AI との対話練習 |
| 記録 | 学習記録、能力別の進捗、覚えたものの再チェック |
| 設定 | AI のオン・オフ、キーの状態、今日の利用回数、起動時の設定 |

練習方法 5 種（[labels.js](../sample/speak-kit/src/app/_lib/labels.js) の `PRACTICE_MODES`）も踏襲する：思い出して答える / 一部を入れ替える / 表現を使い分ける / 意味を選ぶ / 自由に英文を作る。

### 4.2 RPC の名前と応答の形（踏襲）

[rpc-names.mjs](../sample/speak-kit/src/server/rpc-names.mjs) の 18 名と、[envelope.mjs](../sample/speak-kit/src/server/http/envelope.mjs) の同一 envelope を維持する。呼び出し経路だけ `POST /api/<名>` → `google.script.run.rpc(name, request)` に変わる。

### 4.3 AI の可否判定（踏襲）

[context.mjs](../sample/speak-kit/src/server/ai/context.mjs) の `operationContext()` をそのまま移す。

- 1 回の操作の **最初に 1 度だけ**決める。操作の途中で読み直さない
- 決め手は 3 つ：設定の「AI を使う」、キーの有無、今日の利用回数（自前の上限と、無料枠の 429 を受けた記録）
- 使えない理由は 3 つだけ：`setting_off` / `key_missing` / `limit_reached`
- 設定が「使わない」なら、キーがあっても Gemini へ接続しない
- Gemini が 429（無料枠の上限）を返したら、その操作は 4.5 の構造化エラーで返し、その日の残りは `limit_reached` として扱う
- 画面に出す文言は 1 か所（`aiReasonLabel`）

### 4.4 安心して使うための装置（作り替える。理由を明記する）

参照元の [config.mjs](../sample/speak-kit/src/server/config.mjs) と [usage.mjs](../sample/speak-kit/src/server/ai/usage.mjs) にある円表示・自動停止・オン・オフは、**技術的な安全弁ではなく、利用者の心理を軽くするための装置**だった。目玉が有料だったから要った。

Gemini の無料枠（2.2）では請求が起きない。不安の中身が「いくら払うか」から「止まらないか・どこへ送られるか」に変わるので、装置もそれに合わせて作り替える。

| 参照元 | GAS 版 | 役割 |
|---|---|---|
| 利用額の**円**表示（既定 1 ドル = 150 円） | **「無料枠で動いています。料金はかかりません」と今日の利用回数** | 払っていないことが一目で分かる |
| 1 日 2 ドル / 1 か月 20 ドルで**自動停止** | **1 日の回数上限（設定値）。429 を受けたらその日は止める** | 無料枠の上限で突然エラーになる代わりに、理由つきで止まる |
| 設定画面の **AI オン・オフ** | **そのまま** | いつでも止められるという安心。**ブレーキがあるからアクセルを踏める** |
| （無し） | **自由記述と会話の画面に「名前・連絡先などの個人情報を書かない」を常に出す** | 無料枠の入出力は Google の製品改善に使われる（2.2） |

**この装置を「AI は任意だから」の根拠に使わない。** 逆で、AI が中心だから必要になった制御である。

金額の計算（実トークン数から金額を出す、料金表に無いモデルは最高値で数える）は持ち込まない。暦 `Asia/Tokyo` は回数の日次境界として踏襲する。トークン数は `ai_usage` に記録だけする。

### 4.5 AI が止まってもコアは通る（踏襲。ただし床であって目的地ではない）

- AI は 1 か所（`client.mjs` に相当するファイル）からだけ呼ぶ
- クイズ・RPC の振り分けは AI の窓口を参照しない（[ai-isolation.test.mjs](../sample/speak-kit/src/test/ai-isolation.test.mjs) に相当する検査を GAS 側にも置く）
- AI の失敗は構造化エラー（`ai_unavailable` など）で返し、コア操作を落とさない
- 採点できなかった回答は「確認できませんでした」のまま残し、あとで再判定できる

これは**鍵が切れても落ちないための床**である。**AI 無しの状態を完成形として配らない**（2.2）。

### 4.6 出題アルゴリズム（踏襲）

[quiz.mjs](../sample/speak-kit/src/server/services/quiz.mjs) の選択規則を、SQL から JS へ **意味を変えずに**書き直す。

- 間隔（`SPACING = 3`）：直近 3 問に出た対象は後回し
- 昇格（安定）：連続 2 回成功、かつその 2 回が 3 問以上あいている
- 段階ゲート：`form`（英文を書く）は、同じ表現の `meaning` または `intent` に 1 回成功するまで出さない
- 優先順：失敗したもの → 前日以前に成功したもの → 未回答（リセット前に成功済み）→ 未回答 → それ以外
- ルート優先：混同ペアで取り違えたものを最優先、次に `CONTROLLED_RECALL` の証拠が無い表現
- 段階優先：`meaning`・`intent` → `contrast` → `form`
- 当日境界は `Asia/Tokyo`
- 全部安定したら出題を止め、「記録の『覚えたものを再チェック』を押します」の文言を返す（文言ごと踏襲）

### 4.7 回答の記録と採点（踏襲）

- 回答は**追記型台帳**。残高・状態を上書きしない。現在の状態は履歴から導出する
- 同じ `attempt_id` の再送は冪等（`idempotent_replay`）
- 自由記述の採点体系：観測（`meaning_match` / `speech_act_match` / `comprehensibility` / `target_pattern_status` / `issues`）→ [grade.mjs](../sample/speak-kit/src/server/ai/grade.mjs) の `reduceObservation` で `pass` / `pass_with_note` / `retry_target` / `retry_form` / `fail_communication` に落とす
- 学習者向けの文面（`learnerFeedback`）も文字列ごと踏襲する
- 参照元のプロンプトは Claude 向けに調整されている。Gemini で同じ観測と 5 判定が出るかを、校正用の回答セットで確かめてから出荷する（D16、12 優先度A）

### 4.8 教材の正本を利用者のシートにする（**新しくする**）

参照元は教材が YAML にあり、[src/server/content/](../sample/speak-kit/src/server/content/) の 1,001 行で検査・導出して DB に流す。利用者は触れない。表現を 1 つ足すのに YAML 編集 → `data:sync` → デプロイが要る。

GAS 版では、**教材シートそのものが正本**になる。

| | 参照元 | GAS 版 |
|---|---|---|
| 正本 | `data/` の YAML（黒澤のリポジトリ） | **利用者のスプレッドシートの `expressions` シート** |
| 表現を足す | YAML 編集 → `data:sync --apply` → デプロイ | **行を 1 行足す。次の出題から出る** |
| 検査 | `npm run data:check`（schema 350 行超） | シート上の検査関数（必須列・重複キー・選択肢の数） |
| 黒澤の 51 表現 | 唯一の教材 | **初期値**。消しても足しても良い |

これが Sheets を選ぶことで初めて成立する機能であり、**この構想で唯一、参照元より機能が増える点**である。黒澤が選んだ 51 表現は黒澤の課題であって、他人には他人の覚えたい表現がある。

踏襲する規律：`key` は一度決めたら変えない、教材（表現・クイズ）と学習の状態（回答・取り違えた回数）を同じシートに混ぜない。

配布時の初期教材は、`sample/speak-kit/data/` の YAML から生成した JSON を同梱して投入する（D13）。**生成は配布物を作るときの 1 回だけで、以後の正本は利用者のシートである。**

### 4.9 利用者と公開範囲（モデル次第。8.3 で決める）

- モデル A：1 インスタンス＝利用者 1 人。`learnerKey = "default"` のまま
- モデル B・C：1 インスタンスを数人で共有。`learnerKey` をメールアドレス単位に変える

### 4.10 文書と言語（踏襲）

画面の文言・ドキュメント・コメントは日本語。文言は 1 か所に集める。

### 5.1 GAS の制約で、事前に数字を押さえる点

- 実行時間：1 回 6 分。Gemini の 1 往復（数秒）も、会話の 1 ターンも収まる
- `UrlFetchApp`：無料の Google アカウントで 1 日 20,000 回。個人の学習では当たらない
- スプレッドシート：1 ファイル 1,000 万セル
- Gemini の無料枠：回数の上限はプロジェクト単位。1 人 1 本の鍵で、1 日の練習量が収まるかを実測する（12）
- 読み書きの性能：行数が数千を超えたら回答台帳をローテーションする。**閾値と方式は未決**

### 5.2 Postgres / Supabase は採用禁止

**このアプリは関係データベースを一切使わない。** 永続化は Google Sheets、秘密は `PropertiesService`、それだけである。これは「今は使わない」ではなく**禁止**であり、将来の機能追加の理由にもしない。

#### Postgres が担っていた機能は全部ふさがる

| Postgres が担っていた機能 | GAS 版の代替 | 判定 |
|---|---|---|
| 行の保存 | Sheets | ○ |
| トランザクション（`withTransaction`） | `LockService` ＋ 追記専用 | ○ |
| ビュー（`effective_capability_evidence` ほか） | 導出関数 | ○ |
| window 関数・CTE（出題選択） | JS（D2） | ○ |
| スキーマ移行（`sql/migrations`） | シート生成関数 ＋ 版数セル | ○ |
| 接続・認証・プーラー | **不要になる**（接続先が無い） | ○ |
| `grading_claims` による二重採点の防止 | **同期採点で消滅**（D4） | ○ |
| sequence（整数 ID） | `Utilities.getUuid()`。整数が要る所はロック下で max+1 | △ |
| **一意制約（冪等性の担保）** | ロック下で走査してから追記 | **△ コード依存になる** |
| **トリガによる追記専用の強制** | 書き込み関数 1 か所 ＋ シート保護 | **△ 下記** |
| 外部キー | 無し | **× 捨てる** |

**残る損失は 3 つだけで、どれも関係 DB を戻す理由にならない。**

1. **一意制約が無い。** `attempt_id` の再送を冪等にするのは DB ではなくコードの責任になる。`LockService` を取り忘れると、エラーを出さずに二重行が入る。対策は書き込み関数を 1 か所に閉じ、ロック無しの追記を検査で落とすこと（10）
2. **追記専用をトリガで強制できない。** それだけでなく、**利用者はスプレッドシートを開いて回答履歴を直接書き換えられる。** Postgres では不可能だった。4.8 で教材を開放した以上、同じ性質が台帳にも及ぶ。緩和は台帳シートの非表示とシート保護だが、**所有者は解除できるので完全には防げない**。学習記録は「本人が壊せる自分の記録」と割り切る
3. **外部キーが無い。** 参照の整合はコードで保つ

#### 抜け道は 2 つしかないので、そこを塞ぐ

GAS から関係 DB に到達する経路は 2 本だけである。**この 2 行を守れば、禁止は構造として閉じる。**

| # | 規則 | 塞がるもの |
|---|---|---|
| 1 | **`Jdbc` サービスを使わない**（`JdbcService` / `Jdbc.getConnection` など一切） | Cloud SQL、MySQL、SQL Server、Oracle への直接接続。GAS が標準で持つ唯一の DB クライアント |
| 2 | **`UrlFetchApp` の宛先は `generativelanguage.googleapis.com` のみ** | Supabase の REST（PostgREST）、Neon / Turso の HTTP API、その他あらゆるクラウド DB の API |

どちらも grep できる。`Jdbc` の出現と、`UrlFetchApp.fetch` の宛先ホストを検査するテストを置き、**文書だけの禁止にしない**。

#### リポジトリ側の機械ゲート

- `.claude/settings.json` の `psql` / `supabase` / `turso` を **ask → deny** にする（このリポジトリの脅威モデルでは「承認すれば使ってよい」ではなく「使わない」）
- `env/secret.yaml` の雛形から DB 接続の例（`databaseUrl` / `tursoUrl` / `tursoAuthToken`）を消す。空欄があると埋めたくなる
- 秘密は Gemini のキー 1 本だけになる

## 8. 配布

### 8.1 相手の手順

1. 黒澤がコピー元のスプレッドシート（コンテナバインドのスクリプト同梱）を 1 つ用意する
2. 相手にリンクを渡す。相手は「ファイル > コピーを作成」
3. メニューから「初期設定」を実行し、Google の承認を 1 回通す
4. 発行されたウェブアプリの URL を開く
5. **AI を有効にする。** Google AI Studio でキーを発行し、設定画面に貼る（モデルによる。8.3）

（モデル B・C では 2〜3 が無くなり、リンクを開くだけになる。）

### 8.2 相手による改修は対象にしない

相手が編集するのは**教材シートだけ**である（4.8）。コードは直さない。`clasp` による配布、ZIP 配布、コード改修を教える動画は、この構想に**含めない**。機能の追加・変更は黒澤がコピー元を直す。

**例外は作らない。** 要望が出たら別の task に切る。

### 8.3 配布モデル A / B / C（**最重要の未決**）

2.2 のとおり、解くべき問題は「誰の鍵で目玉を動かすか」である。

| | **A: 1 人 1 コピー・各自の鍵** | **B: 1 インスタンス共有・各自の鍵** | **C: 1 インスタンス共有・黒澤の鍵** |
|---|---|---|---|
| 公開設定 | `MYSELF` ＋ `USER_DEPLOYING` | `ANYONE` ＋ `USER_ACCESSING` | `ANYONE` ＋ `USER_ACCESSING` |
| 鍵の置き場 | 各自の `getScriptProperties()` | 各自の `getUserProperties()` | 黒澤の `getScriptProperties()` |
| **相手の AI 設定作業** | **AI Studio でキー発行（カード不要）** | **AI Studio でキー発行（カード不要）** | **無し。リンクを開けば目玉が動く** |
| 無料枠を誰の分で使うか | 相手 | 相手 | **黒澤の 1 プロジェクトの枠を全員で分ける** |
| 入力の送り主（無料枠は製品改善に使われる） | 本人のキー | 本人のキー | **全員の入力が黒澤のキーで送られる** |
| 本人の識別 | 不要 | `getActiveUser().getEmail()` | `getActiveUser().getEmail()` |
| 学習データ | 各自の Drive | 黒澤の Drive に同居 | 黒澤の Drive に同居 |
| **データの見え方** | 本人だけ | **シートを共有するので、全員が全員の行を開ける** | 同左 |
| 機能追加の反映 | 全員にコピーし直してもらう | 黒澤が 1 回直せば全員に届く | 同左 |
| 上限の単位 | インスタンス = 1 人なので参照元と同じ | 同左 | **利用者ごとの回数上限に変える必要あり** |
| README の決定との関係 | 適合 | 「単一ホスト型は不採用」に抵触 | 同左。課金は起きないが、相手の利用量が黒澤名義の枠に載る |

**根本の緊張：** 共有インスタンスでは、本人識別（`USER_ACCESSING` が要る）と データの非公開（シートを共有したくない）が逆を向く。`USER_ACCESSING` にすると各自がシートに直接アクセスできてしまい、`USER_DEPLOYING` にすると識別子が取れない（個人 Gmail では `getActiveUser().getEmail()` が空になるとされる。12 の優先度A で実機確認）。

**C は、目玉を摩擦ゼロで届ける唯一の形である。** Gemini の無料枠では黒澤に請求は起きない。代わりに**1 プロジェクトの回数上限を全員で分け合う**ことになり、人数が増えると 429 で止まる。利用者ごとの回数上限があれば「載るが制御できる」は保てるが、枠そのものは増えない。

**逆に A・B の壁は、Gemini 化で大きく下がった。** 相手の作業は「Anthropic でアカウントを作り、カードを登録し、キーを発行する」から「いまの Google アカウントで AI Studio を開き、キーを発行して貼る」になった（2.2）。

ここでは決めない（13-1）。**決まるまでは A で設計する。** A で相手に残るのは、AI Studio でキーを発行して貼る 1 手順である。

### 8.4 動画

「まず AI 無しで動かす」をセットアップの第 1 歩に置くのは踏襲する。**ただし動画の到達点は AI が動いている状態にする。** AI 無しで終わる動画を作らない。

| リスク | 対策 |
|---|---|
| **相手が Gemini のキーを発行・貼り付けできず、目玉に届かない** | **無料枠でカード登録は消えた。残る手順（AI Studio でキー発行 → 設定画面に貼る）を動画で名指しで見せる。8.3 のモデル選択と合わせて解く。この構想の最大のリスク** |

| モデル C で全員が黒澤の無料枠を分け合い、429 で止まる | 利用者ごとの回数上限（4.4 の機構を人数分に拡張）。実測して打ち切る |
