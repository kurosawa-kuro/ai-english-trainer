# 03 ドメインモデル

正本は [構想](./GAS版AI英会話訓練アプリ構想_ai-english-trainer.md)。用語と状態の定義だけをここに置く。出題規則の根拠は構想 4.6、採点体系は 4.7。

## 用語

| 用語 | 意味 |
|---|---|
| 表現（expression） | 練習の対象になる英語のフレーズ・型。`key` を持ち、一度決めたら変えない。**利用者がシートで編集できる** |
| クイズ項目（quiz item） | 1 つの表現から導出した 1 問。種類は `meaning`（意味を選ぶ）/ `intent`（場面に合う表現）/ `form`（英文を書く）/ `contrast`（使い分け） |
| 回答（attempt） | 1 回の解答。**追記専用**で、上書きしない。同じ `attempt_id` の再送は冪等 |
| 安定（stable） | その項目を連続 2 回成功し、かつその 2 回が 3 問以上あいている状態。安定した項目は出題されない |
| 間隔（spacing） | 直近 3 問に出た対象を後回しにする規則 |
| 段階ゲート | `form` は、同じ表現の `meaning` か `intent` に 1 回成功するまで出さない |
| 混同ペア | 取り違えやすい 2 つの表現の組。取り違えた項目は出題で最優先になる |
| 再チェック（review reset） | 安定した項目をもう一度出題対象に戻す操作 |
| 操作の文脈 | 1 回の操作の最初に 1 度だけ決める、AI を使えるかどうかとその理由 |
| 学習者（learnerKey） | 記録の持ち主。**配布モデル A では `"default"` 固定**。B・C ではメールアドレス（構想 8.3・未決） |

## 状態 / ライフサイクル

### クイズ項目の状態（学習者から見た）

```text
未回答 ──成功──> 1回成功 ──間隔3以上あけて成功──> 安定（出題されない）
   │                 │                                  │
   └──失敗──> 失敗（最優先で再出題）<───────────────────┘
                                          再チェック（review reset）
```

出題の優先順（構想 4.6）:

```text
失敗した項目 > 前日以前に成功した項目 > 未回答（再チェック前に成功済み） > 未回答 > その他
  └ さらに：混同ペアで取り違えた項目を最優先、次に CONTROLLED_RECALL の証拠が無い表現
  └ さらに：meaning・intent > contrast > form の順
```

当日の境界は `Asia/Tokyo`。

### 自由記述の採点結果

AI の観測（`meaning_match` / `speech_act_match` / `comprehensibility` / `target_pattern_status` / `issues`）を、次の 5 つに落とす。

| 判定 | 意味 |
|---|---|
| `pass` | 意味も言い方も合っている |
| `pass_with_note` | 意味は伝わり、細かい揺れがある |
| `retry_target` | 意味は伝わったが、練習対象の表現を使っていない |
| `retry_form` | 意味は伝わったが、その形の一部が足りない |
| `fail_communication` | 意味が届いていない（原因は `MEANING` か `INTENT`） |

採点できなかった回答は「確認できませんでした」のまま残し、あとで再判定できる。

### AI の可否

```text
設定が「使わない」        -> setting_off（鍵があっても接続しない）
鍵が無い                  -> key_missing
今日/今月の上限に到達     -> limit_reached
上記以外                  -> 使える
```

理由は 3 つだけで、画面に出す文言は 1 か所に集める。
