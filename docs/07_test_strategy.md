正本は [構想](./GAS版AI英会話訓練アプリ構想_ai-english-trainer.md)。**まだ実装もテストも無い（`src/` は空）。** ここには、着手時に先に置く検査を定義する。

## 先に置く検査（実装より前）

禁止事項と踏襲項目は、**文書だけでは守られない**。grep かテストで落ちる形にしてから実装に入る。

| # | 検査 | 落とすもの | 根拠 |
|---|---|---|---|
| T1 | `Jdbc` の出現がゼロ | 関係 DB への直接接続 | 構想 5.2 |
| T2 | `UrlFetchApp` の宛先が `api.anthropic.com` のみ | Supabase の REST、他クラウド DB の HTTP API | 構想 5.2 |
| T3 | AI の窓口を import / 参照するのは 1 か所だけ | 出題・記録・RPC 振り分けが AI に依存すること | 構想 4.5 |
| T4 | シートへの書き込みが 1 か所の関数を通る（他から `setValue` を呼ばない） | 追記専用の規律破り | 構想 5.2 |
| T5 | ロック無しの追記が無い | 冪等性の破れ（静かな二重行） | 構想 5.2 |

| T7 | 出題選択の JS 版が、同じ回答履歴に対して参照元 SQL と同じ 1 問を返す | 学習アルゴリズムの意味の変質 | 構想 4.6 |

T7 がこの構想でいちばん重い検査である。**出題規則は SQL から JS へ書き直すので、「動く」だけでは足りず「同じ 1 問を返す」まで確かめる。**

## テスト範囲

| 範囲 | 対象 | 備考 |
|---|---|---|
| 純粋関数 | 答えの正規化、採点の判定表（5 判定）、金額計算、ハッシュ | 参照元の `src/server/domain/` と `ai/grade.mjs` の判定部分を流用できる |
| 出題選択 | 与えた回答履歴 → 次の 1 問 | T7。参照元との比較 |
| シート入出力 | 追記・冪等な再送・ロック | **本物のシートに書かない**（下記） |
| AI の可否 | 設定オフ / 鍵未設定 / 上限到達の 3 理由 | AI を呼ばずに判定できること |
| AI 失敗時 | 401 / 429 / 5xx / タイムアウトでコアが通る | 構想 4.5 |
| 配布 | コピー → 初期設定 → Golden Path | 実機。[08_release_runbook.md](./08_release_runbook.md) |

## 本物のシートに書かない

参照元は使い捨て DB `speak_kit_test` を毎回作り直し、接続先がそれでなければ何も書かずに失敗する規律を持っていた。**同じ規律を踏襲する。**

- テストは専用のスプレッドシートに向ける
- 対象が専用シートでなければ、**何も書かずに失敗する**
- 自分の学習記録が入ったシートに向けてテストを流さない

## 品質ゲート

```bash
# src/ 着手後に埋める。現時点では Makefile は starter の TODO のまま
make test
git diff --check
```

**書いてあるコマンドが動く前提で作業しない。** 開発の道具立て（`clasp` を使うかどうかを含む）は未決で、構想 12 章の優先度A を潰してから決める。

## タスク完了条件

各 task は、完了前に必要な検証を `Verification` に残す。

- 実行したコマンド
- 結果の要約
- 実行できなかった検証と理由
- 残るリスク

中間段（関数が通った・ビルドが緑）だけで完了にしない。**Golden Path の完了状態を実際に観測する**（[01_requirements.md](./01_requirements.md)）。

テスト追加や期待値変更が必要な場合は、task に理由を書き、仕様変更なら先に該当 docs と構想を更新する。
